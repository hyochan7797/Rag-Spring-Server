# RAG 데이터 품질 개선: 희소 청킹 → 풍부한 단일 청크

## 문제 정의

FSS API에서 충분한 데이터를 받아오고 있었지만, 청킹 방식이 잘못되어 RAG 검색이 단편적인 정보만 반환했다.

---

## 변경 전 (Before)

### 청킹 구조 — 상품 1개당 5개의 희소 청크

```
청크 1 (특징):   [bank_name] 우리은행 / [상품명] 우리아파트론
                [상품특징] 없음 / [가입방법] 영업점, 모집인

청크 2 (자격):   [bank_name] 우리은행 / [상품명] 우리아파트론
                [대출신청자격] 영업점, 모집인     ← join_way 중복!

청크 3 (한도):   [bank_name] 우리은행 / [상품명] 우리아파트론
                [대출금액] LTV 70%              ← 달랑 1줄

청크 4 (금리):   [bank_name] 우리은행 / [상품명] 우리아파트론
                [대출금리] [아파트/분할상환/고정] 2.97%~4.78%
                [중도상환수수료] 주택상환금액×1.4%×(대출잔액일수÷3년)

청크 5 (유의):   [bank_name] 우리은행 / [상품명] 우리아파트론
                [연체이자] 3개월 미만: 정상금리+7% ...
                [공시월] 201601
```

### 문제점

| 문제 | 설명 |
|------|------|
| `join_way` 중복 | 특징/자격 청크 둘 다 동일 내용 |
| 텍스트 버림 | `loan_inci_expn`, `erly_rpay_fee`, `dly_rate`의 상세 설명이 잘림 |
| `dcls_strt_day` 미사용 | 공시 시작일 완전 누락 |
| 청크 분리 문제 | "군인" 같은 키워드가 join_way 안에 있어도 다른 청크를 검색하면 매칭 실패 |

## 변경 후 (After)

### 청킹 구조 — 상품 1개당 1개의 풍부한 청크

```
[은행명] 우리은행
[상품명] 우리아파트론
[대출종류] 주택담보대출
[가입방법] 영업점, 모집인
[대출한도] LTV 70%
[부대비용]
- 인지세 : 해당세액의 50%(대출금액 4천만원 이하시 없음)
- 국민주택채권 매입 : 대출금액 × 120% × 1% × 채권할인율
- 주택신보출연료(신규 주택구입시에 한함) : 0.09~0.29%
[중도상환수수료]
- 주택상환금액×1.4%×(대출잔액일수÷3년)
[연체이자율]
- 3개월 미만 : 정상금리 + 7%
- 3개월 이상 : 정상금리 + 8%
  (최고 : 15%)
[금리 옵션]
  · 아파트 / 분할상환방식 / 고정금리: 2.97%~4.78% (평균 3.2%)
  · 아파트 / 만기일시상환방식 / 변동금리: 2.97%~4.78% (평균 3.51%)
  · 아파트 / 분할상환방식 / 변동금리: 2.97%~4.78% (평균 3.21%)
  · 아파트 / 만기일시상환방식 / 고정금리: 2.97%~4.78% (평균 4.3%)
[공시기간] 20160120 ~ 현재 (공시월: 201601)
```

## 개선 효과

| 항목 | Before | After |
|------|--------|-------|
| 상품당 청크 수 | 5개 | 1개 |
| 총 청크 수 | ~595개 | ~119개 |
| 청크당 정보량 | 2~3 필드 | 전체 필드 |
| BM25 키워드 커버 | 청크별로 분산 | 모든 키워드 한 청크에 집중 |
| `join_way` 중복 | 있음 | 제거 |
| 부대비용 상세 | 버려짐 | 전체 보존 |
| 신용등급별 금리 | 평균만 저장 | 1~10등급 전체 저장 |
| 공시 시작일 | 미사용 | 포함 |

총 청크 수가 줄어도 각 청크가 훨씬 풍부하므로 검색 품질이 향상된다.  
"군인대출", "직장인 전용", "아파트 담보" 등 join_way나 부대비용 안에 숨겨진 키워드도 BM25가 찾을 수 있게 됐다.

## 트러블슈팅

### 문제: FSS API 응답의 `dcls_end_day`가 null인 경우 오류

**증상:** `dcls_end_day`가 `null`(JSON) → Python `None` → 문자열 포맷팅 시 `"None"` 출력  
**해결:** `base.get("dcls_end_day") or "현재"` 로 None/빈값 처리

### 문제: 5개 청크 구조에서 join_way가 중복 저장

**증상:** 특징 청크와 자격 청크가 거의 동일한 내용 → 불필요한 중복 검색 결과  
**해결:** 단일 청크로 통합하여 중복 제거

### 문제: 청크 분리로 인한 키워드 미스

**증상:** "군인 대출 가능한 곳" 질문 시 join_way에 "군인" 키워드가 있어도 다른 청크(금리 청크 등)가 검색되어 매칭 실패  
**해결:** 모든 필드가 하나의 청크에 있으므로 어느 필드에 키워드가 있어도 동일하게 검색됨

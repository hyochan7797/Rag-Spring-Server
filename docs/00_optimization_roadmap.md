## 남은 최적화 후보

### 1. 멀티쿼리 검색 (Multi-Query Retrieval)

**개념:** 질문 하나를 LLM으로 3개 표현 변형으로 생성 → 각각 검색 → RRF로 결과 통합

**적용 위치:** `rewrite_query()` 확장 또는 별도 `multi_query_search()` 함수

```
원본: "신한은행 신용대출 금리 얼마야?"

변형 1: "신한은행 신용대출 금리 조건"
변형 2: "신한은행 개인신용대출 이자율"
변형 3: "신한은행 마이너스통장 금리 등급별"

→ 3번 검색 → RRF 통합 → Reranker
```

**기대 효과:** 키워드 선택에 따른 검색 누락 방지. 특히 동의어가 많은 금융 용어에 효과적.

**구현 난이도:** 중 (Gemini 호출 추가, 기존 RRF 재활용)

---

### 2. HyDE (Hypothetical Document Embeddings)

**개념:** 질문에 대한 가상의 이상적인 답변을 LLM으로 생성 → 그 답변을 임베딩해서 Dense 검색에 사용

**원리:** 질문 임베딩보다 답변 형태의 임베딩이 실제 문서 임베딩과 더 가까운 공간에 위치

```
Before: embed("신한은행 신용대출 금리?")          → Qdrant 검색
After:  embed("신한은행 신용대출 금리는 3~6%이며...") → Qdrant 검색
```

**적용 위치:** `search_similar_docs()` 내 Dense 검색 쿼리 생성 부분

**기대 효과:** Dense 검색 정확도 향상. 질문과 문서 임베딩 간 벡터 공간 미스매치 해소.

**구현 난이도:** 하 (Gemini 호출 1번 추가, 임베딩 입력만 교체)

**주의:** 가상 답변이 틀릴 경우 오히려 검색이 나빠질 수 있음 → BM25 결과와 RRF로 보정

### 3. 검색 품질 평가 프레임워크 (Evaluation)

**개념:** 검색 파이프라인 변경 시 품질이 실제로 좋아졌는지 수치로 측정

**지표:**

| 지표 | 설명 |
|---|---|
| Recall@k | 상위 k개 결과에 정답 문서가 포함된 비율 |
| MRR (Mean Reciprocal Rank) | 첫 번째 정답 문서의 순위 역수 평균 |
| NDCG | 순위 가중치를 반영한 검색 품질 지표 |

**구현 방식:**
1. 골든셋 구성: (질문, 정답 상품코드) 쌍 20~50개 수동 작성
2. 파이프라인 변경 전후 각 지표 측정
3. `test_integration.py`에 평가 시나리오 추가

**기대 효과:** 최적화 효과를 주관적 체감이 아닌 수치로 증명 → 포트폴리오 신뢰도 향상

**구현 난이도:** 중 (골든셋 구성이 핵심 공수)

---

### 4. 대화 맥락 기반 필터 자동 업데이트

**개념:** 현재는 현재 질문에서만 필터(은행명, 대출종류)를 추출. 이전 대화에서 언급된 조건을 누적·유지.

```
턴 1: "우리은행 신용대출 알려줘"   → 필터: 우리은행, sinyoung
턴 2: "금리 조건은?"               → 현재: 필터 없음 (새로 추출 실패)
                                     개선: 이전 필터 우리은행, sinyoung 유지
턴 3: "하나은행은?"                → 은행 필터만 하나은행으로 교체
```

**적용 위치:** `ask_chat()` 내 필터 추출 로직, Spring의 `FastApiService.java`에 필터 상태 전달 추가

**기대 효과:** 멀티턴 대화에서 불필요한 재언급 없이 조건 유지

**구현 난이도:** 중 (Spring ↔ FastAPI 간 필터 상태 전달 구조 변경 필요)

---

### 5. 응답 캐싱 (Query Cache)

**개념:** 동일하거나 유사한 질문에 대해 이전 검색 결과를 캐시하여 재사용

**적용 방식:**
- 정확 매칭: Redis에 `hash(question)` → 검색 결과 캐시 (TTL: 1시간)
- 유사 매칭: 임베딩 유사도 기반 캐시 히트 판단 (코사인 유사도 > 0.97)

**기대 효과:** 반복 질문(인기 상품, 공통 금리 문의)에서 응답 지연 90% 감소

**구현 난이도:** 중 (Redis 인프라 추가 필요, docker-compose에 redis 서비스 추가)

